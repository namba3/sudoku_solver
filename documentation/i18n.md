# 翻訳リソース

画面に表示する文言は`locales/`のJSONカタログで管理します。現在のロケールは日本語（`ja`）と英語（`en`）です。キーは原文ではなく、画面上の用途や意味を表す名前にします。

```text
locales/
├── ja.json
└── en.json
```

Rust UIからは`src/i18n.rs`の`Language`と関数を使います。

- `t(language, "action.solve")`は引数のない文言を返します。
- `t_args(language, "parse.line_count", &[("actual", count.to_string())])`は名前付き引数を文中へ挿入します。
- `t_plural(language, "message.conflicts", count, &[])`は数に応じた翻訳形を選んでから引数を挿入します。

引数を含む場合も、文章をプログラム側で連結せず、一文全体をカタログに置きます。たとえば、行数エラーは日本語と英語で語順を変えられます。

```json
{
  "parse.line_count": "9行必要ですが、{actual}行あります。"
}
```

複数形が必要なメッセージは文字列ではなく`one`と`other`を持つオブジェクトにします。日本語は`other`を使い、英語は数が1のとき`one`、それ以外は`other`を使います。

```json
{
  "message.conflicts": {
    "one": "Resolve the conflict in {count} highlighted cell.",
    "other": "Resolve conflicts in {count} highlighted cells."
  }
}
```

未翻訳キーは英語カタログから補完します。英語にもキーがない場合、デバッグビルドでは`[MISSING: key]`、リリースビルドではキー名が表示されます。新しいキーを追加するときは、両方のカタログへ同じキーを追加してください。

この実装の複数形選択は現在の日本語・英語向けに`one` / `other`を扱います。ロケール追加時に複雑なCLDR規則が必要になった場合は、選択規則を拡張するかICU MessageFormatやFluentへの移行を検討します。数値・日付・通貨のlocale formatterは翻訳カタログとは別の責務であり、現状のUIには導入していません。
