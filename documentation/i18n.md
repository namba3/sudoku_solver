# 翻訳リソース

画面に表示する文言はFluent（FTL）形式のリソースで管理します。現在のロケールは日本語（`ja`）と英語（`en`）です。メッセージIDは原文ではなく、画面上の用途や意味を表す名前にします。Rust側ではドット区切りキー（例:`parse.cell_count`）を使い、Fluentではドットをハイフンに置き換えたID（`parse-cell_count`）へ解決します。

```text
locales/
├── ja.ftl
└── en.ftl
```

Rust UIからは`src/i18n.rs`の`Language`と関数を使います。

- `t(language, "action.solve")`は引数のない文言を返します。
- `t_args(language, "parse.cell_count", &[("actual", count.to_string())])`は名前付き変数を文中へ渡します。
- `t_plural(language, "message.conflicts", count, &[])`は数値の`$count`をFluentへ渡し、ロケールに合う複数形を選びます。

変数は`{$name}`と書きます。文章をプログラム側で連結せず、一文全体をリソースに置くことで、日本語と英語で語順を変えられます。

```ftl
parse-cell_count = 改行を除いて81文字必要ですが、{$actual}文字あります。
```

複数形の選択もFTLメッセージ内に記述します。

```ftl
message-conflicts = { $count ->
    [one] Resolve the conflict in {$count} highlighted cell.
   *[other] Resolve conflicts in {$count} highlighted cells.
    }
```

日本語では通常`other`のみを定義します。英語では`one`と`other`を定義します。分岐の規則はロケールに対応するFluent bundleが決めます。

未翻訳メッセージは英語リソースから補完します。英語にもIDがない場合、デバッグビルドでは`[MISSING: key]`、リリースビルドではIDが表示されます。メッセージを追加・削除するときは両方のリソースを更新してください。カタログの構文とIDの一致は`cargo test`で確認します。

数値・日付・通貨の表示形式は翻訳文の責務と分けています。必要になったときはFluentの組み込み関数をbundleへ登録し、該当するメッセージで利用してください。
