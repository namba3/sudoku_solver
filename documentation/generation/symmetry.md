# 対称性正規化

[生成ドキュメント案内](../generation.md)へ戻る。

## 空間変換と数字正規化

`symmetry`はPuzzle MinLex、Solution MinLex、Pairwise直接判定を別APIとして提供します。Fast生成器とブラウザー経路は高コストな正規化APIを呼びません。合法な空間変換はband/stack交換と各band/stack内の置換を組み合わせた各1,296通りに転置を加えた3,359,232通りです。数字置換9!通りは列挙せず、左上からの初出順に数字を割り当てます。

### Puzzle MinLex

`canonicalize_puzzle`は完成盤面を必要としません。各空間変換に対して、まず81セルのヒント配置（空欄0、ヒント1）の辞書順を最小化し、最小配置を実現する全変換だけで数字を初出順に正規化して比較します。1セルごとに現在の最良配置との共通prefixを比較し、最初に大きくなった変換を残りのセル処理前に枝刈りします。配置prefixが一度小さくなった候補は、その後のセル値だけでは枝刈りしません。同じ最小配置を作る別変換は、数字配置が異なることがあるためすべて比較対象に残します。

この2段階化は通常の盤面MinLexと一致します。任意の2変換の出力を左から比較すると、最初に異なるセルが両方空欄か、片方だけヒントです。片方だけヒントなら、ヒント配置の0/1比較が先に勝敗を決めます。配置が同一なら、数字列だけを比較し、各変換で数字置換を自由に選べる最小列が初出順正規化です。よって最小ヒント配置を持つ変換の中で正規化数字列を最小化すれば、盤面全体の最小表現になります。

### Solution MinLex + Automorphism

`canonicalize_solution(puzzle, solution, max_nodes)`は、完成数独の行・列・ブロック整合性、ヒントとの整合性、探索予算内での一意性を検証します。唯一解と確認できない場合はエラーを返します。キーは `(正規化完成盤面, ヒントbitboard)`の辞書順最小です。完成盤面の最小形を作るすべての変換の上でヒント配置も比較する一回の探索なので、複数の最小化変換間の差（完成盤面の自己同型）を明示列挙せずに処理します。bitboardは左上をbit 80、右下をbit 0とし、整数の昇順がセル列の0/1辞書順と一致します。

完成盤面が有効でも、複数解問題の任意の完成盤面を使ったキーは問題同値性を保証しません。このAPIは一意性を自ら検証し、予算切れは`UniquenessUnknown`として失敗させます。キー一致は同値性の必要十分条件です。一意解問題を空間・数字変換すると唯一の完成盤面も同じ変換を受けるため、正規形を実現する全変換におけるヒントbitboardの最小値は変換選択に依存しません。

### Pairwise参照判定

`check_equivalent_pairwise`はCanonical Keyを参照せず、合法変換を直接適用してヒント位置と数字対応を検査します。行/列・band/stackのヒント数分布、ブロック分布、数字出現数の多重集合は不一致なら非同値を確定できる前置フィルタに使います。一致時も全変換探索を省略しません。成立時は空間変換と全単射の数字対応をWitnessとして返し、適用結果を検証できます。変換上限までに結論が出ない場合は`Unknown`です。Pairwiseのセル添字計算は正規化器の共通セル参照関数を呼ばず、返したWitnessを公開`apply`で別途照合します。

`cross_validate`はPuzzle、Solution、Pairwiseの判定を照合し、不一致を明示的なエラーにします。Solution側は両入力の一意性検証に成功する必要があります。共通の`canonicalize` API、実行統計、再生可能Witness、容量指定FIFOキャッシュ、Puzzle一括処理関数もあります。キャッシュは形式バージョンと正規化済み81セル全体をキーに保持し、ハッシュ値単独では照合しません。

### 再現可能なローカル測定

次のコマンドは生成seedを固定し、17ヒントPuzzle MinLex、Solution MinLex、同値Pairwise、30ヒントPuzzle MinLexの経過時間と探索統計を表示します。

```sh
cargo run --release --bin sudoku -- bench symmetry --iterations 5
```

このコマンドは固定seedの入力について、各経路の経過時間と探索統計を表示します。比較時は同じbuild・環境・反復数で実行してください。

正規化の定義とパターン先行法はChristoph Lassの論文「Minimal number of clues for Sudokus」のcanonical minlex節を設計参考にしました。SudokuClassicMinLexの公開READMEは同じ空間群サイズを示し、リポジトリはMITライセンスを掲示しています。本実装はコードを流用せず独立に記述しています。[Lass (2012)](https://doi.org/10.2478/s13537-012-0011-y)、[SudokuClassicMinLex](https://github.com/dclamage/SudokuClassicMinLex)。
